# 크리에이터 아웃리치(이메일 대량 제안) — 셋업 가이드

관리자 전용 · 접근 URL: **`/admin/oc`** (기존 관리자 메뉴에는 노출되지 않음. 로그인 후 직접 URL 접속)

## 전체 흐름
1. **데이터** — 크리에이터 CSV 업로드(브라우저 파싱 → 500행 단위 적재, handle 기준 업서트)
2. **제품·컨셉** — 제품명/브랜드/카테고리/컨셉/USP 등록
3. **크리에이터 필터** — 규모(평균 조회수)·총조회수·영상수·브랜드 이력(카테고리)·지역·이메일 보유로 대상 필터
4. **발송(캠페인)** — 제품 + 발신 메일함 + 제목/본문(변수) + 필터 → 캠페인 생성(수신자 확정) → 배치 발송
5. **발송이력** — 수신자별 상태(sent/failed/queued/skipped)·오류·발송시각
6. **회신함** — 공용 메일함 최근 30일 수신을 크리에이터/캠페인에 매칭·적재
7. **발신계정** — 공용 메일함(allow-list) 관리

> 데이터 특성: 이 데이터셋은 **followers 값이 없어**, 규모 판단은 **평균 조회수(avg_views)** 로 합니다. `brands`(K뷰티 브랜드 이력)는 카테고리/관심 시그널로 필터에 사용합니다.

## 발송·열람 방식 — Workspace 서비스계정 + 도메인 전체 위임(DWD)
앱 비밀번호(SMTP)도, 사용자별 OAuth 동의화면도 사용하지 않습니다. **서버-투-서버 2-legged JWT** 방식입니다.

| 구분 | 방식 |
|---|---|
| 발송 | Gmail API. 서비스계정(`GOOGLE_SA_KEY_JSON`)이 JWT로 공용 메일함을 impersonate → 그 메일함 명의로 발송. scope `gmail.send` |
| 열람 | 같은 서비스계정 위임, scope `gmail.readonly`. `users/{메일함}/messages` (최근 30일, 스팸·휴지통 제외) 읽어 크리에이터/캠페인에 매칭·적재 |

담당자가 앱 비밀번호를 넣거나 매번 OAuth 동의를 누를 필요가 없습니다. Workspace 관리 콘솔에서 서비스계정 client_id에 두 scope의 도메인 위임을 한 번 승인해두면, 지정된 공용 메일함(예: `cs@glovek.space`) 명의로 발송·열람이 동작합니다.

### 설정 (한 번만)
1. **서비스계정 생성** (Google Cloud Console) → JSON 키 발급 → **Gmail API 사용 설정**
2. **Vercel 환경변수** `GOOGLE_SA_KEY_JSON` = 서비스계정 키 JSON 전체 (raw JSON 또는 base64 모두 허용)
3. **Workspace 관리 콘솔 → 보안 → API 제어 → 도메인 전체 위임**에서 서비스계정의 **client_id** 추가, scope 승인:
   - `https://www.googleapis.com/auth/gmail.send`
   - `https://www.googleapis.com/auth/gmail.readonly`
4. `/admin/oc` → 발신계정 → 위임 대상 **공용 메일함**(예: `cs@glovek.space`) 등록 → [테스트]로 확인

> `email` = 위임 대상 메일함이며, 반드시 Workspace 도메인 내 실제 메일함이어야 합니다. 등록된 메일함으로만 발송·열람됩니다.

## 발송 정책 / 한도
- 메일함별 **일일 한도(daily_limit)** 를 두고, 오늘(KST) 발송량을 차감해 남은 만큼만 발송합니다.
- 1회 [발송] 클릭 시 30건 단위 배치로 반복 발송하며 남은 큐가 없거나 일일 한도 소진 시 중단합니다.
- 완만한 발송(건당 ~0.35초 간격)으로 스팸/스로틀을 완화합니다.
- **드라이런**: 실제 발송 없이 수신자·문구를 기록만 하여 사전 점검할 수 있습니다.
- Gmail 발송 한도(참고): Workspace ~2,000/일. daily_limit을 이보다 낮게 설정하세요.

## 회신 매칭(수신함)
- [회신함] 탭에서 메일함 선택 → [최근 30일 동기화] → 수신 메일을 읽어
  - 보낸사람 이메일 = 우리가 발송한 수신자(`oc_messages.to_email`) → **캠페인 매칭**
  - 보낸사람 이메일 = 크리에이터 이메일(`oc_creators.email`) → **핸들 매칭**
  - 결과를 `oc_inbox`에 적재(중복은 갱신).

## 템플릿 변수
제목/본문에서 사용: `{{handle}} {{views}} {{avg_views}} {{total_views}} {{videos}} {{brands}} {{region}} {{profile_url}} {{product}} {{brand}} {{category}} {{concept}} {{usp}}`

## 데이터/보안 메모
- 크리에이터 CSV(약 9.5MB)는 **repo에 커밋하지 않습니다.** 관리자 화면에서 업로드로 적재합니다.
- 서비스계정 키는 DB/코드에 저장하지 않고 Vercel 환경변수(`GOOGLE_SA_KEY_JSON`)에만 둡니다.
- 표 스키마: `oc_creators / oc_products / oc_senders / oc_campaigns / oc_messages / oc_inbox` (db.ts `ensureSchema`에서 자동 생성).
- 코드베이스에 nodemailer/SMTP는 사용하지 않습니다(순수 fetch + Node crypto JWT 서명).

## 향후(브랜드사 오픈)
현재는 관리자 전용입니다. 추후 브랜드사에게 열 경우, 발신 메일함·수신 대상·발송 한도를 브랜드(owner) 단위로 스코프하도록 `oc_*` 테이블에 owner 컬럼을 추가해 확장할 수 있습니다.
