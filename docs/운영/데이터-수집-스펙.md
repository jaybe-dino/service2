# GloveK 데이터 수집 스펙 (Apify 기반) — 파트별 · 데이터 기준

> 목적: 우리가 Apify로 무엇을·어떻게 수집하는지 **데이터 도메인 단위**로 정리. 다른 AI/개발자에게 인수인계용.
> 원천 액터는 2개(영상·샵)이고, 나머지(크리에이터·이메일·통계·추이)는 **파생**이다.
> 스택: Next.js(App Router) · @vercel/postgres(Neon) · Apify actors · 비동기 kick→poll.

---

## 0. 큰 그림

| 원천 | 액터(env) | 과금 | 무엇을 |
|---|---|---|---|
| 영상 | `APIFY_ACTOR` = clockworks/tiktok-scraper | 결과당 $0.003 (비쌈) | 브랜드 관련 틱톡 영상 |
| 샵 | `SHOP_ACTOR` = pratikdani(또는 trakk) | ~$1.60/1k (저렴) | 틱톡샵 상품 |
| 이메일(옵션) | `EMAIL_ACTOR` = scraper-mind/tiktok-profile-email-scraper | 결과당 | 크리에이터 공개 이메일 |

**파생(수집 후 계산):** 크리에이터, 브랜드 통계, 국가 집계, 유도 GMV, 일별 추이, 이메일(bio 추출).

---

## A. 영상 (videos)

- **소스:** 영상 액터(clockworks). 브랜드별 **해시태그**(브랜드명 slug) + **핸들**(있으면)로 검색. 지역(region)별 프록시 타게팅.
- **수집 방법:** 비동기 run 시작 → `collect_jobs`에 기록 → 폴링으로 dataset 회수 → 매핑 → upsert. 크론 `/api/cron/collect`(매시 30분) + 수동 버튼.
- **증분:** `oldestPostDateUnified`(sinceDate)로 **그 이후 게시물만** (재구매 방지).
- **DB 테이블 `videos`:**
  | 컬럼 | 의미 |
  |---|---|
  | video_id (PK) | 틱톡 영상ID (멱등·중복차단) |
  | brand_name | 검색한 브랜드 |
  | handle | 크리에이터 핸들 |
  | views, likes, comments, shares | 지표 |
  | is_ad, is_shop | 광고/샵 콘텐츠 여부 |
  | posted_at | 게시일 |
  | url | 영상 URL |
  | country | 수집 지역(region) 태깅 |
  | product_ref | 영상이 태그한 상품ID(제품↔영상 정밀 매칭) |
  | cover_url | 썸네일(커버) |
- **매핑 시 함께 취득(파생용):** authorMeta.signature(bio), fans(팔로워), verified → creators로.
- **비용/주의:** 결과당 과금 → **1차 백필 깊이(initialLimit)**가 비용 좌우. 기본 150(과거 500=사고).

## B. 크리에이터 (creators) — + 국가별

- **소스:** `videos`에서 **집계 파생**(recomputeCreatorsForBrand). 별도 크롤 아님(단, 이메일 보강은 프로필 재크롤).
- **국가:** 크리에이터 자체 국가 필드는 videos의 country에서 유도(그 크리에이터 영상들의 국가). 상세 API는 `array_agg(country)`로 국가 목록 제공.
- **DB 테이블 `creators`:**
  | 컬럼 | 의미 | 출처 |
  |---|---|---|
  | handle (PK) | 크리에이터 key | videos |
  | videos, total_views, avg_views | 집계 | videos |
  | brands (text[]) | 협업 브랜드 | videos |
  | bio | 프로필 설명 | authorMeta.signature |
  | email | 공개 이메일 | bio 추출 or 이메일 액터 |
  | followers | 팔로워 | authorMeta.fans |
  | verified | 인증 | authorMeta.verified |
  | region | 지역 | (옵션) |
- **파생 지표(읽기 시 계산, API):** engage(참여율), tier(mega/macro/micro), fitScore(적합도 0~100), 유도 GMV(product_ref↔products), 추정 단가.

## C. 샵 · 제품 (products) — + 국가별

- **소스:** 샵 액터. **브랜드명 키워드 + 국가(country_code)**로 상품 검색.
- **수집 방법:** 국가별로 브랜드 run 시작 → 폴링 회수 → upsert. 크론 `/api/cron/collect-shop`(매시) + 수동 버튼.
- **국가 처리:** `product_id = "US:1729..."` 처럼 **국가 프리픽스**로 저장 → 같은 상품이 국가별로 구분 저장. 대상 국가는 `SHOP_COUNTRIES`(어드민 설정 우선).
- **중복 방지:** `retryDays`(기본 14) 동안 같은 (브랜드,국가) 재크롤 안 함. 이미 상품 있는 브랜드는 스킵.
- **DB 테이블 `products`:**
  | 컬럼 | 의미 |
  |---|---|
  | product_id (PK) | "국가:틱톡상품ID" |
  | brand_name | 검색 브랜드 |
  | title, price, currency | 상품 정보 |
  | sold_count | 판매수 |
  | commission_rate | 커미션율(%) — actor가 주면 |
  | url | 상품 URL |
  | country | 수집 국가 |
  | image_url | 썸네일(actor가 주면) |
- **추정 GMV = price × sold_count** (실매출 아님, 라벨 명시).

## D. 이메일 (creators.email)

- **경로 2가지:**
  1. **영상 수집 부산물:** authorMeta.bio에서 정규식 추출(extractEmail, 난독화 일부 복원) → 영상 수집 시 자동 채움.
  2. **전용 이메일 액터(옵션):** `scraper-mind/tiktok-profile-email-scraper` 등을 핸들 목록으로 배치 실행 → email만 채움. (어드민 배치 버튼, env 또는 1회 입력)
- **저장:** `creators.email` (있을 때만). key = handle.
- **외부 수집 지원:** CSV 익스포트(`/api/admin/creators/export`, key=handle) → 외부에서 이메일 채움 → 임포트(`/api/admin/creators/import-emails`)로 handle 기준 되매핑.

## E. 일별 추이 (스냅샷)

- **video_snapshots** (video_id, snap_date, views) — 바이럴 급상승 산출.
- **product_snapshots** (product_id, snap_date, sold_count, price, est_gmv) — 판매·GMV·가격 추이(제품 상세 차트).
- 하루 1행/대상, 당일은 최신값 갱신.

## F. 브랜드 통계 (파생)

- **brand_stats** (videos, influencers, total_views, avg_views, max_views, shop_count) — videos 집계.
- **brand_shop_stats** (products, avg_commission, total_sold, est_gmv) — products 집계.

---

## G. 수집 메커니즘 (공통)

1. **비동기 kick→poll:** Apify run을 "시작만" 하고(빠름) `collect_jobs`에 기록 → 다음 사이클 폴링으로 완료분 dataset 회수·적재. (웹훅 차단 환경에서도 동작)
2. **크론(vercel.json):** collect-shop `0 * * * *`(매시), collect `30 * * * *`(매시 30분).
3. **국가:** 영상=지역 프록시 타게팅(region), 샵=country_code + product_id 프리픽스.
4. **증분/중복방지:** 영상 sinceDate, 샵 retryDays(14), 멱등 upsert(video_id/product_id), 이미-수집 스킵.
5. **통제(어드민, 재배포 없이):** 전체 정지 + 트랙별(영상/샵) on/off + 강도(개수·깊이·주기) + 국가.
6. **안전장치:** 스톨 잡 리핑, 재시도 상한, 백프레셔, 45초 시간예산.

## H. 비용 모델 (중요)

- **액터는 "돌려준 결과마다" 과금** → DB 중복저장은 막아도 구매는 과금됨. 비용 통제 = **적게 요청**(개수·주기·트랙).
- 영상 clockworks $0.003/결과(비쌈) · 샵 ~$1.60/1k(저렴) · 이메일 액터(결과당).
- 사고 사례: 해시태그 8종 × 매시간 재수집 → 같은 영상 반복구매 → 70,924결과 = $213(그 한 줄). 수정: 해시태그 1종·깊이 150·retryDays 14·트랙 OFF·정지스위치.

## I. 현재 상태 (기본값)

- 🎬 영상 트랙: **기본 OFF**(비용 보호). ON 시 매시간 자동.
- 🛍 샵 트랙: **기본 ON**, 매시간 자동(저렴).
- 이메일: 수동 배치.
- 스위치 ON=자동(크론) / OFF=수동 버튼만 / 전체정지=비상.
