# 아웃리치 발송 연동 셋업 가이드

> 대상: glovek 운영/개발. 두 트랙을 각각 켠다 — **A. 이메일(Resend)** · **B. 틱톡 공식 채널(제휴/TTCM)**.
> 공통 원칙: 각 트랙은 **일일 한도(rate limit)** 내에서만 발송. 연동 전에는 "수기 기록"으로 한도만 관리.

---

# A. 이메일 발송 — Resend 셋업

콜드 메일(공개 비즈니스 이메일 대상)을 실제로 발송하려면 Resend + 발신 도메인 인증이 필요합니다.

## A-1. Resend 계정 · 도메인 추가
1. **resend.com** 가입 → 로그인
2. 좌측 **Domains → Add Domain** → `glovek.space` (또는 서브도메인 `mail.glovek.space` 권장 — 메인 도메인 평판 보호)
3. Resend가 표시하는 **DNS 레코드(SPF·DKIM·(DMARC))**를 도메인 DNS에 추가
   - glovek.space DNS 관리처(대개 **Vercel → Domains → glovek.space → DNS**)에 그대로 추가
   - `TXT`(SPF), `CNAME`/`TXT`(DKIM), 권장 `TXT`(DMARC: `v=DMARC1; p=none; rua=mailto:...`)
4. Resend Domains 화면에서 **Verified(초록)** 될 때까지 대기(수분~수시간)

## A-2. API Key 발급
- Resend → **API Keys → Create API Key** (권한: Sending) → 값 복사(1회 노출)

## A-3. Vercel 환경변수 등록 (glovek 프로젝트 → Settings → Environment Variables)
| 변수 | 값(예) | 설명 |
|---|---|---|
| `RESEND_API_KEY` | `re_xxx...` | **필수** — 발송 인증 |
| `RESEND_FROM` | `GloveK Partners <partners@glovek.space>` | **필수** — 인증된 도메인의 발신 주소 |
| `RESEND_REPLY_TO` | `partners@glovek.space` | (선택) 회신 주소 |

→ 저장 후 **Redeploy** (env는 재배포해야 반영)

## A-4. 검증
- 어드민 → 아웃리치 보드 → **발송 패널**에 "Resend 미설정" 배지가 사라지면 연동됨
- **템플릿 선택 → [오늘 배치 발송]** → 실제 발송 + 상태 접촉 전환 확인
- (미설정 상태에서도 **[수기 기록]**으로 한도 프로세스는 동작)

## A-5. 도달성(스팸 회피) 원칙 — 중요
- **일일 한도 소량부터**: 신규 도메인은 하루 20~50건으로 시작 → 2~4주 워밍업하며 증량
- 공개된 **비즈니스 이메일만** 사용, **수신거부(unsubscribe)** 문구 포함
- 개인화(핸들·성과 변수치환) + 텍스트 위주(이미지·링크 남발 금지)
- 반송률 높으면 즉시 감량. DMARC 리포트 모니터링

# B. 틱톡 공식 채널 — 제휴 초대 / TTCM

틱톡 공식 초대는 **이메일과 별개 트랙·별개 일일 한도**입니다. 우리 시스템은 어댑터를 **webhook식**으로 열어놨어요:

```
glovek 아웃리치 → POST {TIKTOK_INVITE_URL}
   헤더: Authorization: Bearer {TIKTOK_INVITE_TOKEN}
   body: { handle, message, productId, channel }
   ← 응답 { ok:true, id } 이면 초대 성공 기록
```

즉 **당신이 "틱톡 초대를 실제로 실행하는 엔드포인트"를 만들고 그 URL만 넣으면** 자동 초대가 켜집니다. 그 엔드포인트가 어떤 공식 채널을 쓰느냐가 아래 두 갈래입니다.

## B-1. (권장) TikTok Shop 제휴 초대 — Affiliate API

이미 상품을 파는 셀러라면 가장 빠른 전환 경로입니다(상품 협업 초대).

**준비 단계**
1. **TikTok Shop Partner Center**(partner.tiktokshop.com) 로그인 — 셀러/파트너 계정
2. **Create App** → `App Key`·`App Secret` 발급 + 필요한 **Affiliate 권한** 신청
3. **OAuth 인증**: 셀러가 앱 승인 → `access_token` + `shop_cipher` 획득(만료 시 refresh)
4. **초대 API 호출**: Affiliate의 "Target Collaboration(지정 초대)" 계열 엔드포인트로 크리에이터에게 상품 협업 초대
   - 요청 서명 필요: 파라미터 정렬 + path로 **HMAC-SHA256(app_secret)** 서명

**glovek 연동 방법**
- 위 서명·토큰 로직을 담은 **얇은 미들웨어 엔드포인트**를 하나 만드세요(예: Vercel Function `/api/tiktok/invite` 또는 별도 서버).
  - 입력: `{ handle, message, productId }`
  - 처리: access_token·shop_cipher로 서명 → TikTok Shop Affiliate 초대 API 호출
  - 출력: `{ ok, id }`
- Vercel env에 등록:
  | 변수 | 값 |
  |---|---|
  | `TIKTOK_INVITE_URL` | `https://<당신 미들웨어>/api/tiktok/invite` |
  | `TIKTOK_INVITE_TOKEN` | 미들웨어 보호용 Bearer(임의 랜덤) |
- → 아웃리치 보드 **🎵 틱톡 공식 초대** 패널에서 "미설정" 배지 사라짐 → **[오늘 배치 초대]** 동작

> ⚠️ 핸들→크리에이터ID 매핑: 초대 API는 보통 creator_id를 요구합니다. 미들웨어에서 handle로 조회(제휴 크리에이터 검색)해 id로 변환하세요.

## B-2. (브랜드 매칭) TikTok Creator Marketplace — TTCM

브랜딩 캠페인·대형 크리에이터엔 공식 매칭 채널.

**준비 단계**
1. **creatormarketplace.tiktok.com** — 브랜드/에이전시 계정 생성 + 심사
2. TTCM에서 크리에이터 검색 → **초대(Invite)** 발송(캠페인 단위)
3. Open API 접근은 **파트너 승인제**라 시간이 걸림 → 초기엔 **콘솔에서 수기 초대** + glovek 보드 **[수기 기록]**으로 일일 한도 관리

**glovek 연동 방법**
- Open API 승인 시 B-1과 동일하게 미들웨어 엔드포인트를 만들어 `TIKTOK_INVITE_URL`에 연결
- 승인 전에는 **수기 기록 트랙**으로 운영(사람이 TTCM에서 초대 → 보드에 기록해 갯수 관리)

## B-3. 연동 전(공식 API 준비 중) 운영법
- `TIKTOK_INVITE_URL` 미설정 → 보드에서 **[수기 기록]** 버튼만 활성
- 담당자가 TikTok Seller Center/TTCM에서 **직접 초대** → 보드에서 [수기 기록] 클릭 → **오늘 N/한도** 집계
- 이렇게 하면 공식 API 없이도 **일일 진행 갯수 관리 프로세스**가 즉시 돌아감

# C. 두 트랙 운영 요약

| | 이메일 | 틱톡 공식 |
|---|---|---|
| 대상 | 공개 이메일 보유 | handle 기반(이메일 불필요) |
| 연동 env | `RESEND_API_KEY`·`RESEND_FROM` | `TIKTOK_INVITE_URL`·`TIKTOK_INVITE_TOKEN` |
| 일일 한도 | 보드에서 설정(기본 50) | 보드에서 설정(기본 20) |
| 연동 전 | 수기 기록 | 수기 기록 |
| 발송 위치 | 보드 → 발송 패널 | 보드 → 🎵 틱톡 공식 초대 패널 |

## 추천 시작 순서
1. **Resend 먼저**(A) — 도메인 인증만 하면 즉시 자동 발송. 하루 30~50건 워밍업.
2. **틱톡은 수기 기록으로 시작**(B-3) → Partner 앱 승인되면 미들웨어 연결로 자동화(B-1).
3. 두 트랙 모두 **일일 한도**로 도달성·정책 리스크 관리.
